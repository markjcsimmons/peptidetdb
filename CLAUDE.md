## Markdown versions for AI agents (added 2026-11-11, commit `7ad0144`)
- Every page in `app/sitemap.ts` has a markdown twin at `<path>.md` (`/` is `/index.md`), plus `/llms-full.txt` (all pages joined). `scripts/build-markdown.ts` runs as npm `postbuild`: it converts the prerendered `.next/server/app/**.html` (`<main>` only) into `public/**/*.md`, and **fails the build** if a sitemap URL has no HTML, converts to almost nothing, or a prerendered page is missing from the sitemap. Generated files are gitignored. Run `npm run markdown` to redo it after a build (it needs `.next` from a build, and no `next dev` running).
- **Adding a page: checklist (the build enforces all three, so a forgotten step fails `npm run build`).** (1) Add the path to `app/sitemap.ts`. (2) Add it to the Guides/Trust list in `app/llms.txt/route.ts` (studies and topics are listed automatically; `LLMS_EXEMPT` in the script is for the rare exception). (3) Make it prerender statically (no on-demand rendering). The `.md` file then appears by itself. The build fails if a page route is missing from the sitemap, a sitemap page has no prerendered HTML or converts to almost nothing, or a page is not linked from `/llms.txt`.
- `next.config.mjs`: `Accept: text/markdown` on any page URL is rewritten to the `.md` file; HTML responses carry `Link: <…md>; rel="alternate"; type="text/markdown"`; `.md` responses carry `Content-Type: text/markdown` and a `Link … rel="canonical"` pointing at the HTML page (so Google treats them as duplicates). `/llms.txt` links to the `.md` versions.
- Visual-only components must carry text: SVG/meters use `role="img"` + `aria-label` (becomes `[label]`), `data-md-text` overrides it (evidence meter reads "Evidence level 4 of 5 — …"), `data-md-skip` removes UI-only things (the study-explorer filters). Internal links in the markdown point to other `.md` files. After adding a new kind of component, read its `.md` output.
- Not yet checked on production: Vercel serving the generated `public/*.md` with the right headers and the `Accept` rewrite. After the first deploy, `curl -sI https://peptidetdb.com/peptides/bpc-157.md` and `curl -s -H 'Accept: text/markdown' https://peptidetdb.com/peptides/bpc-157 | head`. ## Rules for adding or editing a study
1. `npm run study:fetch -- <pmid>`; **read the abstract**; write `finding` and `caveat` **in your own words, from the abstract only** (never paste).
2. Identifiers (PMID/PMCID/DOI) from that script, **never from memory or a record's reference list** (a past bug mixed in other papers' IDs). Authors must be the full PubMed list.
3. `funding` = what the record states (COI/grants). If the record says nothing, omit it (page says "not stated"). Don't say "maker"/"supplier" unless the record does.
4. Anything claimed about a paper that the abstract doesn't support → `unverified`.
5. Update the relevant topic verdict in `lib/topics.ts`, run `npm run study:audit` (must be clean), then build.
6. Cite papers in pages with `<PaperLink id="…" via="pmc|doi|pubmed" />` (unknown id fails the build).
- Metadata titles: keep the page's own part ≤52 chars (Bing limit incl. " | PeptideTDB").
- Legal/regulatory content: primary sources (FDA, HHS, Federal Register), dated, news labelled as news; never call something legal/illegal without a source that says so.
- "No human trials found" means *our PubMed search found none*; say so, never "none exists".
